# 已验证经验与后续改进

## 已验证有效的方法

1. 生成模型负责“食品摄影底图”，程序负责中文和真实包装，稳定性明显高于让模型直接生成整张中文详情页。
2. 先制作单品六页，再生成联系表和长图，可以快速发现跨页风格漂移。
3. 用同一商品底图配合模糊、渐变、深色遮罩和裁切变化，可以低成本保持六页统一。
4. 规格页不编造营养表格，只展示资料支持的产品信息和免责声明，更适合正式电商交付。
5. 包装图保留在米白卡片中，比直接抠图更能兼容 PDF 中分辨率不一、背景复杂的图片。

## 本项目遇到的问题

### PDF 图片提取顺序不等于商品顺序

不能按 `img-000`、`img-001` 直接推断商品，需要用联系表和 PDF 页面逐项核对。

### 部分包装被扁平化

奶芙枣、芝麻枣夹核桃等包装无法作为独立高质量对象直接提取，采用高分辨率 PDF 页面裁切后再嵌入。

### PDF 内嵌中文字体是子集

子集字体缺少部分常用字。脚本加入字形预检，发现缺字立即停止，避免生成方框或空白字。

### 包装规格与表格规格可能不一致

例如礼盒示意包装与表格规格存在差异时，详情页规格字段暂按表格数据展示，但必须在正式上架前由商品方确认。

### 价格提示也属于价格信息

用户要求图片不体现价格后，不仅删除数字价格，也删除“图片不含固定价格”“以商家标价为准”和“基于价格单资料”等间接价格文字。

## 下一阶段建议

- 将商品配置从 Python 字典拆分到 YAML/JSON，方便非开发人员维护。
- 引入完整授权中文字体，消除子集字体限制。
- 增加 OCR 自动检查：价格、错别字、伪文字和规格冲突。
- 增加产品包装自动抠图与清晰度评分。
- 为肉制品、烘焙、冲饮、果干和菌类分别建立背景模板库。
- 生成上架清单，记录每款商品最终确认的规格、配料、营养表和资质来源。
